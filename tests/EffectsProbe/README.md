# 窗口颜色效果回归验证

此测试会短暂显示自己创建的红色目标窗口、黑色背景、颜色校准块及蓝色遮挡窗口。它只修改、捕获和关闭自己的测试窗口，不修改系统颜色设置或其他应用。

需要 Windows 10 2004 或更新系统、支持 Windows.Graphics.Capture 的显卡，以及 .NET 11 SDK。构建和结果默认保存到系统临时目录，源码目录保持干净。

在项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\Run-EffectsProbe.ps1
```

也可以指定 SDK 和构建目录：

```powershell
.\tests\Run-EffectsProbe.ps1 -DotnetPath 'C:\path\to\dotnet.exe' -ArtifactRoot 'C:\temp\WindowPilotEffectTests'
```

测试覆盖：

- 原生 alpha 为 255、3、1、0 时，读取单个目标窗口的原始画面。
- 红色反转为青色，反转、灰度和 50% alpha 叠加后的 GPU 输出及桌面显示。
- 在静态红色窗口上选择 `#20B0E0`，强度 25% 时核对 GPU 与桌面均显示 `#C72C38`，100% 时显示所选颜色。切换成黑色、叠加反色和灰度并调整窗口不透明度时，画面会立即更新。
- 强度归零、隐藏和再次显示后的图层状态，以及滤镜开启时的鼠标命中。两像素的预乘 alpha 纹理分别验证全透明和半透明边缘着色后的颜色与透明度。
- 同一窗口同时显示纯蓝、仅蓝通道差一级的近蓝和红色。精确过滤纯蓝后，透出的背景由绿变白，近蓝和红色仍保持原色。再核对 50% 过滤强度、扩大范围、叠加反色和染色，以及关闭过滤后的桌面像素。
- 用 GPU 纹理核对混合颜色 `#3486DE` 与邻色 `#3486DD` 的精确匹配，检查过滤白色时黑色与灰色仍保留，并验证原本透明及半透明的未匹配像素保持原值。
- 模拟目标持续回写满不透明度，核对独立背景图层上叠加反色、灰度与 50% 透明度的桌面像素、鼠标命中和遮挡恢复。
- 鼠标命中仍落到真实目标窗口。
- 普通窗口及两个置顶窗口之间的遮挡顺序，不提升到无关窗口前方。
- 目标改变大小后继续捕获，静态目标改变参数时立即重绘。
- 最小化、隐藏、恢复、透明度为零时的效果图层生命周期。

测试使用独立颜色校准块检测桌面已存在的整体反色。检测到精确的 RGB 互补关系后，桌面颜色断言先校准再比较；原始采集和 GPU 输出断言不经过此校准。这样不会把宿主显示器的全局颜色处理误判为程序的窗口级效果，也不会改变用户设置。

每次运行都会生成独立的临时结果，结束后写入构建目录内的 `effects-probe.json`。若启动或图形捕获超时，脚本会报告最后进入的测试阶段。

实现为单窗捕获、Win2D 颜色处理及点击穿透图层。为保留真实窗口输入，开启滤镜时原窗口保留 1/255 的非零 alpha；半透明模式下可能残留小于 0.4% 的原始颜色。呈现包含 GPU 读回，在较大窗口会消耗更多资源；3 百万、7 百万和 16 百万像素以上分别降低到约 20、12.5 和 6.25 fps，普通窗口最多约 30 fps。
